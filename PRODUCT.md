# Product

## Register

product

## Users

QA engineers and automation engineers working in a local desktop or browser-compatible Playwright workflow. They author repeatable end-to-end tests, inspect generated TypeScript, record browser actions, and run tests without leaving their project.

## Product Purpose

Playwright Studio translates browser behavior into maintainable Playwright steps and TypeScript while keeping the generated code visible. Success means a QA user can create, edit, validate, save, export, and run a test with explicit control over project files and secrets.

## Brand Personality

Precise, calm, operator-focused. The interface should feel like a trustworthy developer tool: dense enough for real workflows, readable during long authoring sessions, and direct about state, limitations, and errors.

## Anti-references

Avoid marketing-style SaaS surfaces, decorative gradients, neon glow, excessive rounded cards, hidden generated code, ambiguous icon-only controls, and interactions that silently rewrite user-authored steps or files.

## Design Principles

- Readable before decorative: steps, locators, and generated code are primary.
- Visible state: dirty, saved, recording, running, passed, failed, stopped, and unavailable states are explicit.
- Explicit control: save, export, apply, delete, and locator replacement require clear user actions.
- Project-safe behavior: imports, drafts, and recording do not modify user-authored source implicitly.
- Desktop-first, browser-aware: desktop workflows get full controls while browser limitations remain understandable.

## Accessibility & Inclusion

Target WCAG 2.1 AA for the authoring surface. Preserve keyboard access, visible focus rings, semantic labels, inline validation, readable contrast, reduced-motion support, and text alternatives for status communicated by color.
